## 🗂️ Topics Covered

> 🧭 Last week's to-do list and modals now live in `src/pages/`, but only one of them can be
> in `App.vue` at a time. This lesson built a way to switch between them: first a home-made
> **tabs** component (props, `v-for` with an index, `$emit` with a value, `<component :is>`),
> then the real tool for the job, **Vue Router**, with its three kinds of history and the
> difference between a plain link and a `RouterLink`.

### 1. 📑 Bulma's tabs as a component

The next Bulma component on the list is **tabs**, a simple menu-like row of titles
(<https://bulma.io/documentation/components/tabs/#alignment>). It has many variants (icons,
sizes, boxed and toggle styles) and they can be combined; the centered one was used here.
The markup went into a new file, `src/components/Tabs.vue`.

A side note on the empty `readme.md` in the project: it is left empty on purpose for you.
If you keep forgetting how to install the packages or start the dev server, write it down
there, for yourself and for whoever touches the project next. After a few months away from
a project you will not remember the commands either.

When the tabs were placed in `App.vue`, the bottom line did not reach from edge to edge.
That is the `container` limiting the width, so `<Tabs>` went **above** the container instead
of inside it.

![tabs](https://api.memegen.link/images/yuno/Tabs_component/Y_U_NO_take_the_titles_as_props.png)

### 2. 🔢 Props, `v-for` with an index, and which tab is active

Copied straight from the docs, the titles are **hard-coded**: there is no way to rename
them or use the component somewhere else with different titles. So the titles became a
prop, an array, and the list item is repeated with `v-for`.

Next, the **active** tab (Bulma's `is-active` class on the `<li>`). Like the modal's `active`
last week this is a prop, but now it is not just true or false: it has to say *which* tab is
active. The title text is a poor choice, because two menu items may well have the same text.
The **position** in the array is unique, so `active` is a number starting from 0.

To get the position inside `v-for`, write the loop variable in parentheses. The order is the
one that is easy to forget: **value first, then key**, `(title, key)`. Printing
`title + key` for a moment showed `Item 1 0`, `Item 2 1` and so on, so the order was right.

The class is the same object form as last week. The key `is-active` has a hyphen, so it
needs quotes, and its value is now a comparison instead of a boolean:

```vue
<script setup>
defineProps(['titles', 'active']);
</script>

<template>
    <div class="tabs is-centered">
        <ul>
            <li v-for="(title,key) in titles" :class="{'is-active': active === key}" @click="$emit('change', key)">
                <a>{{ title }}</a>
            </li>
        </ul>
    </div>
</template>
```

### 3. 📤 `$emit` with a value and `$event`

Clicking a tab should change the active one, but **a prop may not be changed** inside the
component. Same rule as last week: the component sends an event up and the parent decides.
The difference from last week's `close` is that the parent now needs to know *what* to
change to, so the event carries a value: `$emit('change', key)`.

On the parent side, the value sent with the event is available as **`$event`**:

```vue
<Tabs :titles="tabTitles" :active="activeTab" @change="activeTab = $event"></Tabs>
```

Something has to change on the page too, so a `contents` array was added in the same order
as the titles, and the heading shows `{{ contents[activeTab] }}`. Since the array itself is
never changed, it does not have to be a `ref`; a plain array is enough.

![emit](https://api.memegen.link/images/exit/Change_the_active_prop_myself/$emit('change',_key)/Tabs.vue.png)

### 4. 🧩 Whole pages in the tabs: `<component :is>`

Switching text is not very exciting. The to-do list and the modals from earlier lessons are
waiting in `src/pages/`, so the tab titles became `ToDo` and `Modals`, and `contents` now
holds the imported **components** instead of strings.

First the imports inside the pages had to be fixed. Last week they were moved from `src/`
into `src/pages/`, but they still said `./components/...`. The `.` means "the folder I am in",
which is now `pages/`, and there is no `components` folder there. `..` goes one folder up to
`src/`, where `components/` lives:

```js
import ItemList from '../components/ItemList.vue';
```

Printing a component with `{{ }}` just dumps it as an object. To **render** it, Vue has a
built-in element, `<component>`, and its `is` attribute says which component to show:

```vue
<component :is="contents[activeTab]"></component>
```

Now clicking a tab looks like changing pages. It is not, though: only most of the page
content is swapped. The address bar never changes, and a **refresh** always lands back on the
first tab. That logic could be written by hand, but every framework already has a ready
solution for it.

### 5. 🛤️ Vue Router

The thing that remembers which "page" you are on is called a **router**, and almost every
framework has one (React Router and so on). Vue's is **Vue Router**
(<https://router.vuejs.org/>). It is installed like any package, here with
`bun add vue-router` (npm works just as well).

The getting started guide
(<https://router.vuejs.org/guide/#Creating-the-router-instance>) shows the setup. It went into
`src/index.js`: a list of **routes**, each an address `path` and the `component` to show,
a router created from them, and `app.use(router)` before mounting:

```js
import { createMemoryHistory, createRouter } from 'vue-router';

import ToDo from './pages/ToDo.vue';
import Modals from './pages/Modals.vue';

const routes = [
  { path: '/', component: ToDo, name: 'ToDo'},
  { path: '/modals', component: Modals, name: 'Modals'},
];

export const router = createRouter({
  history: createMemoryHistory(),
  routes,
});
```

Nothing changed on the page at first, because `App.vue` still showed the old tabs. With them
removed, the router adds two components of its own that do not even need importing:

- **`<RouterView />`**: "whatever page we are on, show it here". The home page (the to-do
  list) appeared.
- **`<RouterLink to="/modals">`**: a link to a route. A quick test with two of them worked,
  and `/modals` matches the `path` given in `routes`.

![router](https://api.memegen.link/images/light/Everything_in_router.getRoutes()/becomes_a_tab.png)

### 6. 🗂️ A `RouterTabs` component

Rewriting `Tabs.vue` for the router would make it useless for its original job, so a
separate `RouterTabs.vue` was started from a clean copy of the Bulma markup.

To build the tabs, the component needs the list of all routes. The docs' Composition API
page (<https://router.vuejs.org/guide/advanced/composition-api.html#Accessing-the-Router-and-current-Route-inside-setup>)
shows `useRouter()` and `useRoute()`. Logging both in the console was a good way to look
inside: the router has a function **`getRoutes()`** (a function, so it shows nothing until it
is called) that returns every route with its `path`. To get a nice title for each tab, a
`name` was added to the routes, and it showed up there too.

In the end the setup code was not needed at all: in the template the router is available as
**`$router`** and the current route as **`$route`**. The active tab compares the path of the
tab being printed with the path of the current route:

```vue
<li v-for="route in $router.getRoutes()" :class="{'is-active': route.path === $route.path }">
    <RouterLink :to="route.path">{{ route.name }}</RouterLink>
</li>
```

`App.vue` shrank to just this:

```vue
<template>
  <RouterTabs></RouterTabs>
  <RouterView />
</template>
```

### 7. #️⃣ Memory, hash and web history

After all that, a refresh *still* went back to the to-do list. The reason is the
`createMemoryHistory()` from the guide: it keeps the current page only in memory. The router
offers two more kinds.

**`createWebHashHistory()`** puts the route after a `#` in the address, and now a refresh
on the modals page stays there. What is the `#` for? You have seen it all over the links in
these lessons: documentation pages (Bulma's included) put it on headings, and clicking one
adds `#something` to the address and jumps to that spot **without reloading the page**. It
is an in-page link to the element with that `id`. Anything after the `#` is never sent to the
server, and if no element has that id, nothing happens: you can write slashes and any
nonsense there. JavaScript, however, can read it, and that is what the router uses to decide
which page to show.

**`createWebHistory()`** gives clean addresses like `/modals`, without a `#`. The catch: the
browser asks the **server** for `/modals`, and a normal web server answers 404 because there
is no such file. The server has to be set up to return the app for any address. Vite's dev
server already does that (even a made-up path several folders deep loads the app), so this
is what the project ended up with:

```js
export const router = createRouter({
  history: createWebHistory(),
  routes,
});
```

![hash](https://api.memegen.link/images/morpheus/What_if_I_told_you/the_server_never_sees_the_part_after_the_~h.png)

### 8. 🔗 `<a href>` vs `RouterLink`: a single page app

Why bother with `RouterLink` when a normal `<a href="/modals">` also seems to work? Both
switched pages, and with addresses written by hand both kept working. The difference shows
when watching the page closely: a plain link is a **real** link, so the browser throws the
page away, sends a new request and loads everything again. `RouterLink` catches the click in
JavaScript, changes the address bar itself and swaps the content. Nothing is downloaded
again, because the app is already loaded. The back button still works.

This is a **single page application**: it feels like separate pages, but it is all one page.

![link](https://api.memegen.link/images/ackbar/A_plain_~la_href~g_in_a_single_page_app/It's_a_full_page_reload.png)

At the very end, a look further ahead: some web apps keep working **offline**. Tahvel's
timetable is one: open it once, go offline, and it still shows. A **service worker** runs in
the background in the browser, has downloaded the files the app needs, and serves them when
there is no connection. Search for "progressive web app" to read more; it is a topic for a
later lesson.

## ✅ Takeaways

1. **Hard-coded content makes a component single-use**; pass titles in as props and repeat
   them with `v-for`.
2. **`v-for="(value, key) in list"`**: value first, then the index. Use the index, not the
   text, to mark the active item.
3. **`$emit('change', key)` sends a value up**; the parent reads it as `$event`.
4. **`<component :is="...">` renders a component chosen at run time**, and `..` in an import
   goes one folder up.
5. **Vue Router** maps addresses to components: `routes`, `app.use(router)`, `<RouterView />`
   for the page and `<RouterLink>` for links. `$router` and `$route` work in any template.
6. **Memory history forgets on refresh, hash history uses `#`, web history needs the server**
   to return the app for every path.
7. **Use `RouterLink`, not `<a href>`**, inside the app: it changes the page without
   reloading it, which is what makes a single page application.
