### 1. 🛠️ Getting the project running again

The lesson began with a quick setup round for anyone whose machine did not have the project
yet: install Bun, open a **new** terminal after installing a command line program (on
Windows the old one does not see it yet), clone the project, run `bun install` to fetch all
the packages listed in `package.json`, and start the dev server with `bun run dev`.

Then a short recap of where the code stands: the router added two lessons ago, with
`RouterTabs` showing a tab for every route and `RouterView` showing the current page.

### 2. 🔘 Bulma's button

The modal and the tabs were the more complicated components; most of those are done. The
next one is much simpler: the button
(<https://bulma.io/documentation/elements/button/>). Any element with the `button` class
already looks like a nice button, and the docs page shows how much more can be set with
classes alone:

- **colours**: `is-primary`, `is-link`, `is-info`, `is-success`, `is-warning`, `is-danger`
- **sizes**: `is-small`, `is-normal`, `is-medium`, `is-large`
- **styles**: `is-outlined`, `is-rounded`, `is-light` and others
- **states**: hover, focus, active, `is-loading`, and the `disabled` attribute

You could keep writing these classes by hand on every button. But UI frameworks almost
always ship their own `Button` component, where the colour and size are chosen with a short
attribute instead of a string of classes, and every button in the app is guaranteed to look
the same. That is what we are building towards.

![mordor](https://api.memegen.link/images/mordor/One_does_not_simply/copy_the_Bulma_classes_onto_every_button_by_hand.png)

### 3. 🧩 A `Btn` component with a slot

The component went into `src/components/Btn.vue`. The text of a button changes from one
button to the next, so it must not be hard-coded. Writing it as
`<Btn>Cool button</Btn>`, the way a normal `<button>` is used, is the natural form, and it
is exactly what a **slot** does: whatever is written between the component's opening and
closing tags goes in the place of `<slot>`. The same trick was used in the modal component on 12.10.

```vue
<script setup>

</script>
<template>
    <button class="button">
        <slot></slot>
    </button>
</template>
```

![slot](https://api.memegen.link/images/aag/I_am_not_saying_it_is_the_modal/but_it_is_the_same_slot.png)

### 4. 📄 A Buttons page and a new route

To try it out, a separate page for the button examples, `src/pages/Buttons.vue`. The
component is imported from one folder up (`..`), since the page lives in `pages/`:

```vue
<script setup>
import Btn from '../components/Btn.vue';


</script>

<template>
    <Btn>Cool button</Btn>
</template>
```

Creating the file is not enough for it to show up: the page only exists for the app once it
is in the router's list of routes. One import and one line in `src/index.js`:

```js
import Buttons from './pages/Buttons.vue';
const routes = [
  { path: '/', component: ToDo, name: 'ToDo'},
  { path: '/modals', component: Modals, name: 'Modals'},
  { path: '/buttons', component: Buttons, name: 'Buttons'},
];
```

Because `RouterTabs` builds its tabs from `$router.getRoutes()`, a **Buttons** tab appeared
next to ToDo and Modals without touching the tabs component at all.

For now `Btn` always looks the same. Passing the colour and size in as props, and checking
that only allowed values come in, is where the next lesson continues.

## ✅ Takeaways

1. **After installing a command line tool, open a new terminal**; then `bun install` and
   `bun run dev` bring a cloned project to life.
2. **Bulma's button is configured with classes** for colour, size, style and state.
3. **Wrapping it in a `Btn` component** is what UI frameworks do: one place decides how
   every button looks.
4. **`<slot>` lets the component be used like a normal tag**, with the text between the
   tags.
5. **A new page needs a route**; with `RouterTabs` reading the routes, the tab appears by
   itself.
