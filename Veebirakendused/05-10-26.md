### 1. 🧱 Bulma layout: addons, container, spacing, content

The last lesson's button and input were replaced with something from Bulma's form docs:
a text field and a button stuck together, called **form addons**
(<https://bulma.io/documentation/form/general/#form-addons>):

```html
<div class="container content mt-3">
  <div class="field has-addons">
    <div class="control is-expanded">
      <input class="input" type="text" placeholder="Find a repository">
    </div>
    <div class="control">
      <button class="button is-info">
        Add
      </button>
    </div>
  </div>
```

Then four classes to make it sit nicely:

- **`container`** pulls the content in from the edges of the window, with different
  maximum widths at different screen sizes (breakpoints):
  <https://bulma.io/documentation/layout/container/>. Watch that the opening and closing
  tags still match after wrapping things in a new `div`.
- **`mt-3`** adds a bit of room above it. Same spacing helper pattern as last week: `m` or
  `p`, then a direction (`t`, `b`, `l`, `r`, `x`, `y`, or nothing for all sides), then a
  size: <https://bulma.io/documentation/helpers/spacing-helpers/>
- **`is-expanded`** makes the field as wide as possible while leaving room for the button.
  Note that it goes on the **`control`** around the input, not on the input itself, as the
  docs example shows.
- **`content`**: a plain `<ul>` showed up without bullet points. Bulma resets the default
  styles of plain elements; to get normal typography for lists, headings and paragraphs
  back, wrap them in `content`: <https://bulma.io/documentation/elements/content/>. Classes
  can be combined on one element in any order.

### 2. 🔁 A list from an array: `v-for`

Writing out three `<li>` elements by hand is fine. A hundred is not. The items went into an
array, and Vue repeats the element for each one:

```vue
<script setup>
import { ref } from 'vue';

let items = ref(['Piim', 'Viin', 'Sai', 'Mac']);
</script>
```

```html
<ul>
  <li v-for="item in items">{{ item }}</li>
</ul>
```

`v-for="item in items"` goes through the array and creates one `<li>` per element, with
`item` holding the current one. The names are up to you; the convention is a plural for
the array and its singular for one element.

![v-for](https://api.memegen.link/images/money/One_v--for/Shut_up_and_render_my_100_items.png)

### 3. ➕ Adding items, and `.value` in the script

A second `ref` for the text field, tied to it with `v-model`, and a function for the
button:

```js
let newItem = ref('');

function add(){
  if(newItem.value.trim() !== '') {
    items.value.push(newItem.value.trim());
  }
  newItem.value = '';
}
```

```html
<input @keydown.enter="add" v-model="newItem" class="input" type="text" placeholder="Find a repository">
<!-- ... -->
<button @click="add" class="button is-info">
```

The first version did not work, and the console said why: `push` is not a function. In
the template Vue unwraps refs for you, but **in the script a ref's value is behind
`.value`**: `items.value.push(...)`, `newItem.value`. Remember this one, it trips everyone.

Setting `newItem.value = ''` empties the input after adding, because `v-model` works both
ways: change the variable and the field follows.

![.value](https://api.memegen.link/images/spongebob/items.push()/iTeMs.VaLuE.pUsH().png)

### 4. 🧹 No empty items, and Enter to add

Clicking Add with an empty field added empty rows. A check against the empty string fixed
that, but a few spaces still got through. **`trim()`** removes spaces from the beginning
and end, so text made of only spaces becomes empty. The trimmed value is also what gets
pushed: there is no reason to store extra spaces around an item.

`trim()` does not catch everything (Unicode has more invisible, space-like characters),
and a list could also refuse duplicates. Both are doable; try them at home if you like.

**`@keydown.enter`** runs `add` when Enter is pressed in the field. Keep the button
anyway: on a phone or for less technical users, a visible button is what they look for.

![trim](https://api.memegen.link/images/snek/An_item_made_of_three_spaces~q/trim()_says_no.png)

### 5. ✅ Items as objects, and `:key`

To mark items done, a string is not enough. Each item became an object:

```js
let i = 0;
let items = ref([
  {id:i++, text:'Piim', isDone: false},
  {id:i++, text:'Viin', isDone: true},
  {id:i++, text:'Sai', isDone: false},
  {id:i++, text:'Mac', isDone: true},
]);
```

`i++` gives the current value of `i` and then increases it, so the ids come out 0, 1, 2, 3
without typing them. New items get `isDone: false`, since something just added is not done
yet:

```js
items.value.push({id:i++, text: newItem.value.trim(), isDone: false});
```

Printing `{{ item }}` now shows the whole object, so the template prints `item.text`, with
a checkbox bound to `isDone`:

```html
<li v-for="item in items" :key="item.id">
  {{ item.text }}
  <input type="checkbox" v-model="item.isDone">
</li>
```

A plain checkbox, by the way: Bulma leaves checkboxes mostly unstyled.

**`:key`** gives Vue a unique id for every element it draws. Lists that only grow work
without it, but once items move between lists or disappear, Vue can reuse the wrong element
and the page shows something odd even though the data is correct. With a key it knows which
element is which.

Editor tricks from rewriting the four items: **Alt + click** places several cursors, and
**End** / **Home** jump every cursor to the end or start of its line, even when the lines
have different lengths.

### 6. 🧮 `computed` and `filter`: done and to-do

The list was copied twice, under the headings Done Items and ToDo Items, but all three
showed everything. The filtered lists are **computed** values: values that are worked out
from other reactive values and recalculated when those change.

```js
import { computed, ref } from 'vue';

let doneItems = computed(() => items.value.filter(item => item.isDone));
let toDoItems = computed(() => items.value.filter(item => !item.isDone));
```

- **`filter`** goes through the array and keeps the elements for which the function
  returns true. `isDone` is already a boolean, so it can be returned as is.
- **`!`** flips the boolean, so the second list keeps exactly the opposite.
- The arrow functions started out long (braces, `return`) and were shortened: when the body
  is a single expression, the braces and `return` can go.

Tick a checkbox and the item moves between the lists by itself.

![computed](https://api.memegen.link/images/both/Done_items_or_ToDo_items~q/Why_not_both~q_computed().png)

### 7. 🧩 A component: `ItemList.vue`

The same block was now in the template three times. That is the point to stop and think:
if the three copies should behave the same, changing one and forgetting the others is a bug
waiting to happen. Don't repeat yourself.

The repeated part went into its own file, `src/ItemList.vue` (component names start with a
capital letter):

```vue
<script setup>
defineProps(['items', 'title']);
</script>

<template>
    <h1>{{ title }}</h1>
    <ul>
      <li v-for="item in items" :key="item.id">
        {{ item.text }}
        <input type="checkbox" v-model="item.isDone">
      </li>
    </ul>
</template>
```

At first the component knew nothing about `items`: the console warned that the property
was not defined. A component only sees what it is given. **`defineProps`** declares what it
accepts. Props are like the attributes of an HTML element:

```html
<ItemList :items="items" title="All Items"></ItemList>
<ItemList :items="doneItems" title="Done Items"></ItemList>
<ItemList :items="toDoItems" title="ToDo Items"></ItemList>
```

- **`:items`** (with the colon) passes the *value* of a variable.
- **`title`** (no colon) passes the text as written, which is what a fixed heading needs.

The editor's Vue extension can add the `import ItemList from './ItemList.vue';` line when
you type the tag; if it does not, add it yourself. Every frontend framework has components
like this; it is how pages are built from reusable pieces.

## ✅ Takeaways

1. **Bulma**: `field has-addons` joins an input and a button, `is-expanded` goes on the
   `control`, `content` brings back normal list styles.
2. **`v-for`** draws one element per array item; give it a `:key`.
3. **In the script, a ref's value is `.value`**; in the template it is not.
4. **`trim()` before checking for empty**, and `@keydown.enter` for keyboard users.
5. **`computed` + `filter`** derive new lists that update by themselves.
6. **Repeated markup becomes a component**; `defineProps` declares what it accepts, `:` passes
   a variable, no colon passes text.
