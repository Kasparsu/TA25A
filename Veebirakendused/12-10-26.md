### 2. 🪟 Bulma's modal

Bulma has many ready components; most are just styling, but the **modal** is one that
should actually *do* something. It is everywhere on the web (click a picture on Facebook or
Instagram and it opens over the rest of the page):
<https://bulma.io/documentation/components/modal/#image-modal>.

The parts, as they ended up in the component:

```vue
<div class="modal" :class="{ 'is-active': active }">
    <div class="modal-background" @click="$emit('close')"></div>
    <div class="modal-content">
        <slot></slot>
    </div>
    <button class="modal-close is-large" aria-label="close" @click="$emit('close')"></button>
</div>
```

- **`modal-background`** is the dark layer over the page.
- **`modal-content`** can hold anything: an image, a card, a form.
- **`modal-close`** is the X in the corner.

The first example in the docs copies in empty and shows nothing, because it has no
content. The **image modal** example further down has a picture in it, which makes a better
start. The docs also say Bulma ships **no JavaScript**: nothing opens the modal for you.
What makes it visible is one more class, **`is-active`**. Adding it by hand showed the modal
on top of everything; the rest of the lesson was about adding and removing it from Vue.

### 3. 🔀 Toggling a class: ternary, then an object

A `ref` holds whether the modal is open, starting at `false`, and a button sets it:

```vue
<button class="button is-primary" @click="modal1Open = true">Open Modal 1</button>
```

The class was first built with the **conditional (ternary) operator**, the one-line `if`
that most languages have: `condition ? valueIfTrue : valueIfFalse`
(<https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Conditional_operator>).
It works, but repeats `modal` twice. Vue's `:class` has a neater form: a plain `class` for
what is always there, plus `:class` with an **object** whose keys are class names and whose
values say whether the class is on:

```vue
<div class="modal" :class="{ 'is-active': active }">
```

One catch: written without quotes, the key `is-active` is red in the editor. An object key
without quotes cannot contain a hyphen (JavaScript reads it as `is` minus `active`). In
quotes it is fine. Single quotes, because the attribute already uses double ones.

Closing: the X button and the dark background both set the value back. Clicking the
content itself does nothing, which is what you want.

![is-active](https://api.memegen.link/images/inigo/You_keep_writing_is--active_as_an_object_key/I_do_not_think_it_means_what_you_think_it_means.png)

### 4. 📤 A `Modal` component: props down, events up

One modal is fine; a page with several would mean copying the whole block. So it became
`Modal.vue`, and the name `modal1Open` inside it became the more general **`active`**
prop:

```vue
<script setup>
defineProps(['active']);
</script>
```

Opening worked, closing did not. The console explained: **props are read-only**. The
component may not change a value it was given. It used to be merely forbidden; now Vue
blocks it outright, and for a good reason. In a big page, components sit inside components inside
components, ten or twenty levels deep. If any of them could change the data passed to
them, finding *who* changed something during a bug hunt would be close to impossible.

So data goes **down** through props, and news goes **up** through **events**. Just like an
element fires `click`, a component can fire its own event with **`$emit`**, giving it a
name that says what happened (`close`). The parent listens with `@` exactly as for a click
and decides what to do:

```vue
<Modal 
  :active="modal1Open"
  @close="modal1Open = false"
  >
```

The component asks to be closed; the owner of the data closes it. Sending data back up
with the event is also possible and comes in a later example.

![emit](https://api.memegen.link/images/fetch/Stop_trying_to_change_a_prop_inside_the_component/$emit('close')_and_let_the_parent_do_it.png)

### 5. 🐻 A second modal and placeholder images

With a component, a second modal is a second ref and a second button
(`is-success` for a green one). To tell the two apart, the image address became a prop
too, `url`, bound to the image's `src` with `:src`.

Where to get test pictures: there are placeholder services that return an image of the
size in the address:

- <https://placekittens.com/> and <https://placebear.com/>: work, but the choice of
  pictures is small and some sizes come back different each time.
- <https://picsum.photos/> ("Lorem Picsum", after the *lorem ipsum* filler text): the best
  of the bunch. A random photo on every load, a fixed photo by id, or a **seed**: any word
  in the address always gives the same random photo. Extras go after a `?` as **query
  parameters**: `grayscale`, `blur` (with a strength from 1 to 10), and several combined
  with `&`.

Then a surprise: both modals showed the **same** "random" photo. That is the browser, not
the service. When it sees the exact same address twice it reuses the picture it already
downloaded instead of asking the server again (caching). The fix is to make the addresses
differ. Picsum's docs suggest `?random=1`, but any query parameter the server ignores will
do, so a short `?r=1` and `?r=2` are enough:

```vue
<ImgModal :active="modal2Open" @close="modal2Open = false" url="https://picsum.photos/1280/960?r=2"></ImgModal>
```

![cache](https://api.memegen.link/images/same/Modal_1_random_photo/Modal_2_random_photo/Browser_cache:_they're_the_same_picture.png)

### 6. 📦 Any content: `v-html`, then `<slot>`

A modal does not have to hold a picture. To put a Bulma **box** in it
(<https://bulma.io/documentation/elements/box/>), the first idea was another prop with the
HTML as a string. That runs into problems quickly:

- quotes inside quotes (the attribute uses double quotes, the class inside the string
  single ones, and the text inside that would need a third kind);
- printing it with `{{ }}` shows the tags as **text**, because mustaches always print text;
- Vue's **`v-html`** does render it, but needs a wrapper element and is clumsy for anything
  bigger than a line.

The better tool is the **`<slot>`**. Inside the component, `<slot></slot>` marks the spot
where whatever is written *between* the component's opening and closing tags will appear:

```vue
<Modal 
  :active="modal1Open"
  @close="modal1Open = false"
  >
  <div class='box'>I'm in a box.</div>
</Modal>
```

Write the content like normal HTML, and it lands inside `modal-content`.

![slot](https://api.memegen.link/images/box/What's_in_the_modal~q!/Whatever_you_put_in_the_~lslot~g.png)

### 7. 🖼️ A component built on a component: `ImgModal`

The image version was still handy, and writing the `<p class="image">` part every time is
not. So a new component wraps the general one:

```vue
<script setup>
import Modal from './Modal.vue';

defineProps(['active', 'url']);
</script>
<template>
    <Modal :active="active">
        <p class="image is-4by3">
            <img :src="url" alt="">
        </p>
    </Modal>
</template>
```

It takes `active` and `url`, passes `active` on to `Modal`, and puts the image in the slot.
The `close` event is not handled here at all: a listener that a component does not declare
falls through to its root element, which is the `Modal`, so `@close` on `ImgModal` still
works. Building a specific component out of a general one is a normal pattern, and the
reason the components got their own folder.

## ✅ Takeaways

1. **Bulma's modal has no JavaScript**: it is visible when it has `is-active`, and Vue
   adds and removes that class.
2. **`:class` takes an object** (`{ 'is-active': active }`); quote keys that contain a
   hyphen.
3. **Props go down and are read-only.** A component asks for a change with
   `$emit('close')`, and the parent listens with `@close`.
4. **The browser caches identical addresses**; add a different query parameter to get a
   different "random" image.
5. **`<slot>` lets a component hold any content** written between its tags, much nicer
   than passing HTML as a string to `v-html`.
6. **Specific components can be built from general ones** (`ImgModal` uses `Modal`); keep
   them in `components/`, pages in `pages/`, and fix the imports after moving files.
