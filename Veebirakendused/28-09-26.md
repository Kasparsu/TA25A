### 1. 🧱 Bulma in the project

Of the frameworks looked at last week, **Bulma** fits what we want to build best (Bootstrap
you will most likely meet in another subject, and the core ideas are largely the same).
It is installed as a package and pulled in through Sass, replacing last week's example
styles:

```scss
@use "bulma/sass";
```

Then it is all classes in the HTML:

```html
<div class="container">
    <button class="button is-primary my-3">Click me!</button>
    <div class="notification is-primary">
        <button class="delete"></button>
        Primar lorem ipsum dolor sit amet, ...
    </div>
</div>
```

- **`container`** centres the content and gives it a sensible maximum width.
- **`button`** makes a button look like one; **`is-primary`** picks its colour.
- **`notification`** is a ready-made coloured box, with a `delete` button for the close
  cross.
- **`my-3`** is a spacing helper: **m**argin on the **y** axis (top and bottom), size 3.
  Learn the pattern once (`m`/`p`, then `t`/`b`/`l`/`r`/`x`/`y`, then a size) and you
  rarely need hand-written margins.

Docs: <https://bulma.io/documentation/>, and the pages used in class:
[button](https://bulma.io/documentation/elements/button/),
[container](https://bulma.io/documentation/layout/container/),
[spacing helpers](https://bulma.io/documentation/helpers/spacing-helpers/),
[notification](https://bulma.io/documentation/elements/notification/).

### 2. 🎛️ Customizing Bulma's Sass variables

Because Bulma comes in as Sass, its variables can be set at the moment it is loaded.
One line changes the primary colour everywhere it is used:

```scss
@use "bulma/sass" with (
    $primary: coral
);
```

Every `is-primary` button, notification and link is now coral, without overriding a single
selector. This is the main reason to use a framework through Sass instead of a ready-made
CSS file.

### 3. 🖐️ The same thing in plain JavaScript

Two small behaviours, written by hand. A button that toggles its colour:

```js
let button = document.getElementById('button');
button.addEventListener('click', () => {
    if(button.classList.contains('is-primary')) {
        button.classList.replace('is-primary', 'is-warning');
    } else {
        button.classList.replace('is-warning', 'is-primary');
    }
});
```

And a text field whose content is shown reversed in a heading as you type:

```js
let input = document.querySelector('#input');
let reverseText = document.querySelector('#reverse-text');

input.addEventListener('input', () => {
    reverseText.innerHTML = input.value.split('').reverse().join('');
});
```

The pattern: **find the element, listen for an event, change the element**. A string has
no `reverse()`, so it is split into an array of characters, reversed, and joined back.

Most of what jQuery was once needed for can now be done like this, as
<https://youmightnotneedjquery.com/> shows side by side.

### 4. 🗺️ The framework landscape

Plain JavaScript keeps the state in the page: to know whether the button is primary, you
ask the element. Frameworks turn that around. A short look at the big names:

- <https://angular.dev/>: a full, opinionated framework, common in large companies
- <https://react.dev/>: the largest ecosystem
- <https://vuejs.org/guide/quick-start.html>: what we use
- <https://www.solidjs.com/>: React-like syntax, finer-grained reactivity

### 5. 🟩 The same page in Vue

Vue goes into the Vite project through its plugin
(<https://github.com/vitejs/vite-plugin-vue/blob/main/packages/plugin-vue/README.md#vitejsplugin-vue->):

```js
// vite.config.js
import vue from '@vitejs/plugin-vue';

export default {
  plugins: [vue()],
}
```

`index.html` shrinks to one empty `<div id="app"></div>`, and `index.js` mounts the
**root component** into it
(<https://vuejs.org/guide/essentials/application.html#the-root-component>):

```js
import { createApp } from 'vue';
import App from './App.vue';

const app = createApp(App);
app.mount('#app');
```

Both behaviours from section 3 now fit in one `App.vue`:

```vue
<script setup>
import { ref } from 'vue';

    let isPrimary = ref(true);
    let text = ref('');
</script>

<template>
    <button @click="isPrimary=!isPrimary" class="button" :class="{'is-primary': isPrimary, 'is-warning': !isPrimary}">Click me!</button>
    <input type="text" class="input" v-model="text">
    <h1>{{ text.split('').reverse().join('') }}</h1>
</template>
```

- **`ref()`** makes a value reactive: when it changes, everything that uses it updates.
- **`@click`** attaches the event listener right on the element.
- **`:class`** takes an object: each class is on when its value is true. No `contains`, no
  `replace`.
- **`v-model`** ties the input and `text` together in both directions.
- **`{{ }}`** prints a value, and can hold an expression, like the reversing chain.

No `getElementById`, no `querySelector`, no `innerHTML`. The state lives in JavaScript and
the page follows it.

## ✅ Takeaways

1. **Bulma through Sass**: classes like `button`, `is-primary`, `container`, `my-3` in the
   HTML, and variables like `$primary` set once with `@use ... with`.
2. **Plain JavaScript**: find the element, listen for an event, change the element. The
   state lives in the page.
3. **A framework inverts that**: state in JavaScript, the page follows it.
4. **Vue basics**: `createApp` mounts the root component; `ref`, `@click`, `:class`,
   `v-model` and `{{ }}` replace the hand-written DOM code.
