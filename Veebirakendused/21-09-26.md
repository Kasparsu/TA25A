## 🗂️ Topics Covered

> 📦 One `<script>` tag becomes a project: files that import each other, styles that get
> compiled, and a dev server that updates the page without reloading it.

### 1. 🧩 JavaScript modules

```js
// greet.js
export function greet(name) {
    return `Tere, ${name}!`;
}

// main.js
import { greet } from './greet.js';
console.log(greet('TA25A'));
```

Before modules, every script shared one global namespace and the only thing deciding what
was available was the order of your `<script>` tags. With `import` / `export`:

- each file states **what it offers** and **what it needs**
- nothing leaks into the global scope by accident
- the tooling can follow the imports and work out what actually gets used

`export default` exports one main thing per file; named exports let a file offer several.

### 2. 🎨 CSS as part of the build

```js
import './style.css';
```

Importing a stylesheet from JavaScript looks wrong the first time you see it. The point is
that the bundler now *knows* the CSS belongs to this code: it can bundle it, hash it and
ship only what is reachable, instead of you maintaining a list of `<link>` tags by hand.

### 3. 💅 Sass

```scss
$primary: #3b82f6;

.card {
    color: $primary;

    &:hover {
        color: darken($primary, 10%);
    }
}
```

What Sass adds over plain CSS:

- **variables**: one place to change a colour, instead of hunting hex codes
- **nesting**: structure that mirrors the markup
- **`&`**: refers to the current selector, which is how you write `:hover` without
  repeating the class name
- **partials and `@use`**: split styles across files and compile them into one

### 4. ⚡ Hot Module Replacement

The dev server swaps the changed module into the running page instead of reloading it.
Practically: edit a stylesheet, watch the colours change, and whatever you had typed into
a form is still there.

Worth understanding rather than just enjoying: when HMR *cannot* apply a change safely it
falls back to a full reload, and knowing why saves confusion later.

Read: <https://beyondthecode.medium.com/understanding-hot-module-replacement-hmr-f13f66cb5ada>

## ✅ Takeaways

1. **Modules replace load order with declared dependencies.** Each file says what it needs.
2. **Importing CSS from JS** lets the bundler own the styles too.
3. **Sass gives you variables, nesting and `&`**, and compiles to ordinary CSS.
4. **HMR swaps modules in place**, so state survives an edit.
5. **A framework is someone else's opinions.** Useful, but know what you are accepting.
