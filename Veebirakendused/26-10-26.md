### 1. 🧭 Where the project stands

The last few lessons built up `ta25alearnfront`: a `ToDo` page with a shopping list, a
reusable `ItemList` component, modals, tabs and finally Vue Router with `RouterTabs` and
`RouterView`. The list is where today's work continues. Every item is an object with an
`id`, a `text` and an `isDone` flag, and the page shows the same `ItemList` three times
through two computed values:

```js
let items = ref([
  {id:i++, text:'Piim', isDone: false},
  {id:i++, text:'Viin', isDone: true},
  {id:i++, text:'Sai', isDone: false},
  {id:i++, text:'Mac', isDone: true},
]);
```

```js
let doneItems = computed(() => items.value.filter(item => item.isDone));
let toDoItems = computed(() => items.value.filter(item => !item.isDone));
```

If you did not have the project on your machine yet, clone your own copy, run
`bun install` and `bun run dev`, and continue from the code committed on 19.10.

### 2. ⭐ Importance for every item

The task: every item gets an **importance**. What the levels are is up to you: high,
medium and low, or something like critical down to minor. The starting data should have
items of different importance, and when a new item is added on the `ToDo` page, its
importance can be chosen too (for example a `<select>` next to the text field, bound with
its own `v-model` ref, just like `newItem` is for the text).

If an item gets the wrong importance, it should be possible to change it, and the lists
have to follow the change straight away. That is what reactivity is for: change the data,
and everything computed from it updates.

![importance](https://api.memegen.link/images/rollsafe/Cannot_buy_the_Mac_before_the_milk/if_the_list_is_sorted_by_importance.png)

### 3. 🔃 Sorting by importance

All three lists (all, done, to do) are shown **most important first**. The natural place
for this is `ToDo.vue`, as `computed` values next to `doneItems` and `toDoItems`, so the
sorted lists recalculate themselves whenever an item is added, ticked off or changes
importance.

One trap: JavaScript's `sort()` sorts the array **in place**. Sorting `items.value` itself
would reorder the original list. Sort a copy instead (spread it into a new array first,
`[...items.value]`, then sort that).

![sort a copy](https://api.memegen.link/images/officespace/Yeah,_if_you_could_sort_a_copy/instead_of_items.value_itself,_that_would_be_great.png)

### 4. 🎨 Colour coding

Inside `ItemList`, the colour of an item depends on its importance: the most important red,
the least important green and the middle one something in between, like yellow. Everyone
can pick their own colours. Bulma already has colour classes for text and tags
(`has-text-danger`, `has-text-warning`, `has-text-success`, or `tag is-danger` and so on),
and the `:class` binding from the modal and tabs lessons is the way to switch them on.

**Optional extra:** a new page `src/pages/Important.vue` that shows only the most important
items with the same `ItemList`, added to the routes in `src/index.js`, so it appears as a
new tab in `RouterTabs` by itself. For that, both pages need the **same** list: move the
`items` ref out of `ToDo.vue` into its own file (for example `src/items.js`, exported) and
import it on both pages.

## ✅ Takeaways

1. **Every item gets an importance**, chosen when the item is added and changeable later.
2. **Sort in a `computed`**, so the lists follow every change on their own.
3. **`sort()` changes the array it is called on**; sort a copy (`[...items.value]`), not
   the original.
4. **Colour by importance with `:class`** and Bulma's colour classes.
5. **One commit per part, with a message that says what it does**, on top of the lesson
   commits, and a project that starts cleanly from a fresh clone.
